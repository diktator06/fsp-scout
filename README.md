# Скаут

Платформа подбора ИТ-специалистов с **обратной механикой** и верифицированным профилем участника
Федерации спортивного программирования (ФСП). Работодатель сам находит кандидата в базе, где
специалисты разложены по категориям, и приглашает его с обязательной вилкой зарплаты. Категорию
кандидату присваивает не резюме, а опрос и адаптивный тест.

Спецтрек ФСП, «Лидеры цифровой трансформации 2026». Сопроводительная документация —
[PDF](docs/submission/scout-documentation.pdf) и [DOCX](docs/submission/scout-documentation.docx).

## Запуск

Стенд одинаково запускается на Windows, macOS и Linux: всё работает в Docker, ставить Python,
Node.js и базу данных не нужно. Интернет нужен только при первой сборке, дальше стенд работает
офлайн, без GPU и внешних сервисов.

### 1. Установите Docker

| ОС | Что поставить |
|---|---|
| Windows 10/11 | [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/) с бэкендом WSL 2. Если установщик попросит, включите WSL 2 (`wsl --install` в PowerShell от администратора) и перезагрузите компьютер |
| macOS (Apple Silicon и Intel) | [Docker Desktop](https://docs.docker.com/desktop/setup/install/mac-install/) для своего процессора |
| Linux | [Docker Engine](https://docs.docker.com/engine/install/) и плагин Compose (пакет `docker-compose-plugin`) |

Запустите Docker Desktop и дождитесь статуса «Engine running». Проверка — в терминале
(на Windows — PowerShell) должна напечататься версия 2.x:

```bash
docker compose version
```

Стенду нужно около 2 ГБ памяти Docker (с Keycloak — 3 ГБ; в Docker Desktop это
Settings → Resources) и около 3 ГБ на диске.

### 2. Скачайте проект

```bash
git clone https://github.com/diktator06/fsp-scout.git
cd fsp-scout
```

Без Git: на GitHub нажмите Code → Download ZIP, распакуйте архив и откройте терминал в этой папке.

### 3. Запустите

```bash
docker compose up --build -d
```

Первая сборка занимает 5–10 минут, следующие запуски — меньше минуты. Бэкенд сам применяет
миграции, наполняет справочники, создаёт демо-аккаунты и около 120 синтетических кандидатов.
Стенд готов, когда все пять сервисов в состоянии `healthy`:

```bash
docker compose ps
```

### 4. Откройте

| Что | Адрес |
|---|---|
| Приложение | http://localhost:8080 |
| Письма подтверждения и уведомления (Mailpit) | http://localhost:8025 |
| ФСП ID и реестр достижений (эмулятор) | http://localhost:8090 |
| Swagger UI всех методов API | http://localhost:8080/api/docs |

Подойдёт любой современный браузер: Chrome, Edge, Firefox, Safari, Яндекс Браузер.

Остановить стенд, сохранив данные:

```bash
docker compose down
```

Начать заново с чистыми данными:

```bash
docker compose down -v --remove-orphans
```

Файл `.env` не нужен: значения по умолчанию заданы в `docker-compose.yml`. Если что-то нужно
поменять, например порты, скопируйте [.env.example](.env.example) в `.env`.

### ФСП ID на полноценном Keycloak

По умолчанию вход участника ФСП обслуживает лёгкий эмулятор с тем же протоколом (OIDC). ТЗ
строит ФСП ID на Keycloak, поэтому в репозитории есть готовый realm и стенд с настоящим
Keycloak 26:

```bash
docker compose -f docker-compose.yml -f docker-compose.keycloak.yml up --build -d
```

Keycloak поднимается на http://localhost:8081 (админка `admin` / `admin`, только для локального
стенда), участники и пароль — те же, что в эмуляторе. Код бэкенда не меняется, переключаются
только переменные окружения. Вернуться к эмулятору:

```bash
docker compose -f docker-compose.yml -f docker-compose.keycloak.yml down
```

```bash
docker compose up -d
```

Пошаговая проверка в браузере — [docs/KEYCLOAK_GUIDE.md](docs/KEYCLOAK_GUIDE.md).

## Если что-то пошло не так

| Симптом | Что сделать |
|---|---|
| `Cannot connect to the Docker daemon` или `error during connect` | Docker не запущен: откройте Docker Desktop и дождитесь «Engine running». На Linux — `sudo systemctl start docker`, а команды запускайте через `sudo` или добавьте себя в группу `docker` |
| Windows: Docker Desktop не стартует, просит WSL | В PowerShell от администратора выполните `wsl --install`, перезагрузитесь; в BIOS должна быть включена виртуализация |
| `port is already allocated` или `address already in use` | Порт занят другой программой. Скопируйте `.env.example` в `.env` и поменяйте порт: 8080 — `FRONTEND_HOST_PORT` (и `FRONTEND_URL`), 8025 — `MAILPIT_UI_HOST_PORT`, 8090 — `FSP_HOST_PORT` (и `FSP_PUBLIC_URL`), 5432 — `POSTGRES_HOST_PORT` (часто занят установленным PostgreSQL), 8000 — `BACKEND_HOST_PORT`, 8081 — `KEYCLOAK_HOST_PORT` |
| Сервис не становится `healthy` | `docker compose logs backend` (или имя другого сервиса). Первый старт с наполнением данных занимает 1–2 минуты; если контейнер перезапускается, проверьте, что Docker выделено не меньше 2 ГБ памяти |
| Нужно начать с чистыми данными | `docker compose down -v --remove-orphans`, затем `docker compose up --build -d` |
| Письмо не пришло | Все письма стенда ловит Mailpit: http://localhost:8025 |
| Keycloak долго стартует | Первый запуск импортирует realm, это 30–60 секунд; бэкенд ждёт его готовности |
| Интерфейс выглядит слишком мелким или крупным | Проверьте масштаб страницы в браузере: `Ctrl+0` (Windows, Linux) или `Cmd+0` (macOS) возвращает 100 %. Размер шрифта сам подстраивается под ширину окна |

## Демо-доступы

Тестовые учётные записи локального стенда, пароль у всех `ScoutDemo2026`. На странице входа их
можно подставить одной кнопкой.

| Роль | Email | Что внутри |
|---|---|---|
| Специалист | `candidate@example.com` | Чистый аккаунт: онбординг, тест и привязка ФСП проходятся с нуля |
| Специалисты для жюри | `jury1@example.com` … `jury5@example.com` | Пять таких же чистых аккаунтов: каждый проверяющий проходит путь с нуля и пересдаёт тест, не мешая другим |
| Работодатель | `employer@example.com` | Компания «Кедр Технологии»: две потребности (подборка строится при первом открытии), три вакансии с откликами, микрозадачи с ответами |
| Методист | `methodist@example.com` | Справочники, банк заданий, экран «Вакансия → тест», настройки оценки, модерация |
| Синтетические кандидаты | `demo.<специализация>.<номер>@example.com`, например `demo.backend.01@example.com` | Прошли тест настоящим сервисом оценки; около трети привязаны к ФСП |

**Участники ФСП в эмуляторе.** Боевого ФСП ID у команд нет, поэтому в стенде работает эмулятор
с тем же протоколом (OIDC, как у Keycloak). Участники вымышленные, пароль у всех `FspDemo2026`.
Четыре демо-персоны на странице входа эмулятора выбираются одной кнопкой:

| Логин | История в реестре |
|---|---|
| `fsp000021` | 7 соревнований, побед и призов: 6 |
| `fsp000030` | 3 соревнования, одно призовое место |
| `fsp000012` | одно участие без призового места |
| `fsp000007` | ФСП ID есть, участий нет |

## Сценарий для жюри

Базовый сценарий целиком — 10–15 минут. Каждый шаг можно пройти отдельно.

**Кандидат**

- [ ] **Регистрация.** http://localhost:8080 → «Я специалист» → email и пароль, согласие на
  обработку данных. Письмо придёт в [Mailpit](http://localhost:8025), ссылка из него подтвердит
  email и откроет кабинет. *Чтобы пропустить этот шаг, войдите как `candidate@example.com` или
  любой из чистых аккаунтов `jury1…jury5@example.com`.*
- [ ] **Онбординг.** «Заполнить» → имя, стаж, формат → опрос: например, «Разработка» →
  «Backend-разработка», стек `питон`, `fastapi`, `postgres`, уровень Middle. До старта видно,
  из каких тем соберётся тест.
- [ ] **Экспресс-тест.** Режим «Экспресс» → 6–8 заданий на 5–10 минут: код на Python, SQL по
  таблице, задачи на HTTP, архитектуру, конкурентность. Ожидаем: результат на шкале уровней с
  интервалом, разбор по темам и категорию «Backend-разработка · Middle», если тест пройден.
- [ ] **Публикация.** На экране результата — «Опубликовать профиль»: это отдельное согласие,
  без него работодатели кандидата не видят.
- [ ] **ФСП.** «Достижения ФСП» → согласие → «Привязать ФСП ID» → на странице эмулятора выберите
  `fsp000021`. Ожидаем: семь участий с местами и протоколами, балл ФСП с разложением и
  уведомление «Индекс профиля: было → стало».

**Работодатель** (`employer@example.com`)

- [ ] **Потребность текстом.** «Новая потребность» → опишите своими словами, например: «Ищем
  бэкендера уровня мидл в команду лояльности. Нужны питон, FastAPI и постгрес, желательно Docker.
  Удалённо, до 280 тыс. на руки, от 200 тыс.» → «Разобрать текст». Ожидаем: специализация, грейд,
  обязательные и желательные навыки, вилка и формат с пометкой, откуда взято каждое поле.
- [ ] **Подборка.** «Сохранить и подобрать кандидатов» → рекомендованные категории с рыночным
  срезом и ранжированная выдача. У каждого кандидата балл, полоса вкладов и «Почему в подборке».
  Кандидат из первых шагов тоже будет в выдаче, если опубликовал профиль.
- [ ] **Уточнение.** Закрепите любого кандидата без ФСП → «Уточнить и рынок» → «Есть
  подтверждённые участия в ФСП» → «Применить». Ожидаем: версия 2, закреплённый кандидат остался
  с пометкой «не проходит новые фильтры».
- [ ] **Приглашение.** «Пригласить» → вилка «от–до» обязательна, база НДФЛ указана явно →
  «Отправить приглашение».

**Кандидат снова**

- [ ] **Принятие.** Колокольчик или «Приглашения» → компания и вилка видны сразу → «Принять и
  открыть контакты». Ожидаем: контакты работодателя у кандидата, у работодателя — ФИО и email
  кандидата в карточке и статус «Принято» в «Приглашениях».

**Дополнительно**

- [ ] **Кандидат без ФСП.** В «Банке кандидатов» откройте любого кандидата без бейджа «ФСП»:
  карточка и объяснения корректны, вместо достижений — нейтральное «Профиль ФСП не привязан».
- [ ] **Вход через ФСП ID.** Выйдите и нажмите «Войти через ФСП ID» с тем же участником
  эмулятора — откроется кабинет того, к кому он привязан.
- [ ] **Готовая потребность.** У `employer@example.com` в «Подборках» есть «Python-разработчик
  в команду платежей»: при открытии подборка строится на синтетических кандидатах; войти любым
  из них можно паролем `ScoutDemo2026`.

**Дополнительный функционал (критерий №6)**

- [ ] **Резюме из PDF.** Кандидат → «Профиль» → «Заполнить из резюме» → любой PDF-резюме,
  например выгрузка с hh.ru или LinkedIn. Ожидаем: черновик с ФИО, контактами, городом, стеком и
  софт-скиллами, ролями, местами работы, образованием, «О себе», форматом работы, переездом,
  стажем и подсказкой грейда для опроса. Поля переносятся в анкету по выбору, файл не
  сохраняется.
- [ ] **Вакансии и отклик.** Кандидат после опроса → «Вакансии»: лента по баллу соответствия с
  объяснением → вакансия → «Откликнуться» с согласием на раскрытие контактов. Работодатель видит
  отклик с баллом в «Вакансиях», отвечает «Пригласить на собеседование» или «Отказать» с причиной.
  Вакансию можно создать из любой потребности — форма заполнится из неё.
- [ ] **Микрозадачи.** Кандидат → «Микрозадачи»: задача от компании своей специализации,
  «решить» проверяется сразу, «предложить подход» оценивает компания. Фактор актуальности M
  виден с вкладом в индекс. Работодатель → «Микрозадачи»: свои задачи, ответы и оценка подхода
  по рубрике.
- [ ] **Жалоба и модерация.** Кандидат → вакансия или приглашение → «Пожаловаться». После жалоб
  трёх разных кандидатов компания уходит на проверку: у работодателя баннер, публикации и
  приглашения закрыты. Методист → «Модерация» подтверждает или отклоняет жалобу и снимает
  ограничение. В карточке компании у кандидата — репутация из фактов. Вакансия с вилкой в разы
  выше рынка помечается.
- [ ] **ATS.** Работодатель → «Интеграции» → «Подключить песочницу» → «Проверить связь». Через пару
  секунд в журнале «Доставлено», подпись проверена песочницей. Примите приглашение или
  откликнитесь кандидатом — в журнале появится событие с карточкой. Там же выгрузка CSV и JSON.
- [ ] **Keycloak.** Запустите стенд с Keycloak (раздел «Запуск») → кандидат → «Достижения ФСП» →
  «Привязать ФСП ID» → страница входа Keycloak, `fsp000021` / `FspDemo2026`.
- [ ] **Мобильная версия.** Все кабинеты работают на ширине телефона от 375 px: меню в «бургере»,
  карточки в одну колонку, без горизонтальной прокрутки.
- [ ] **Вакансия → тест.** Методист → «Вакансия → тест» → любая вакансия: категория, состав теста
  под её стек, три самых информативных у порога семейства с экземплярами, покрытие навыков.
  «Банк заданий» → семейство → «Сгенерировать другие»: три кандидата — три разных экземпляра.
  Работодатель → «Вакансии» → вакансия → «Как проверяются навыки»: тот же расчёт по своей
  вакансии, но без самих заданий — шаблоны не должны утекать участникам рынка.
- [ ] **Пересдача.** Кандидат, не подтвердивший уровень, сразу может пройти тест на уровень ниже;
  тот же уровень открывается через сутки. Для нескольких попыток подряд удобны аккаунты
  `jury1…jury5`.
- [ ] **Мои данные.** Меню аккаунта → «Мои данные» → «Скачать мои данные» (JSON) и «Удалить
  аккаунт» с подтверждением email.

## Что работает

- **Регистрация и вход.** Email с подтверждением, согласие на обработку ПДн, access-JWT с
  claims как у Keycloak, ротация refresh-токена в httpOnly-cookie, роли кандидат / работодатель /
  методист. Вход через ФСП ID для привязанных аккаунтов.
- **Путь кандидата.** Анкета, опрос о стеке, заявленный грейд с пометкой «не подтверждён»,
  адаптивный тест на 79 параметрических семействах (IRT 3PL, EAP по ходу теста и WLE для итога,
  классификационная остановка).
  Профиль с выгрузкой в PDF, приватность полей и отдельное согласие на публикацию в банке.
- **Путь работодателя.** Потребность из свободного текста, рекомендованные категории с рыночным
  срезом, подборка с объяснением, версии уточнений с сохранением закреплённых, банк кандидатов
  с фильтрами по категории, специализации, грейду, стеку и подтверждённым достижениям ФСП.
- **Приглашения.** Обязательная вилка «от–до» не шире чем вдвое, статусы видны обеим сторонам,
  контакты раскрываются только после принятия, раскрытие пишется в аудит. Уведомления в кабинете и
  письма в Mailpit, дневная квота приглашений.
- **ФСП.** Привязка ФСП ID по OIDC (PKCE, RS256, JWKS) с отдельным согласием, синхронизация
  участий, отвязка с удалением данных. Балл ФСП входит в индекс профиля без ранжирования по уровню
  и дисциплине; отсутствие привязки или истории не штрафуется. Работает и с эмулятором, и с
  полноценным Keycloak.
- **Вакансии и отклики.** Прямые вакансии с обязательной вилкой и лимитом публикаций, лента
  кандидата по баллу соответствия, отклик с раскрытием контактов по согласию, статусы и отказ с
  причиной.
- **Микрозадачи.** «Решить» с автопроверкой по эталону на сервере и «предложить подход» с
  оценкой по рубрике. Раз в неделю система предлагает задачу, результат входит в индекс как
  фактор актуальности M.
- **Резюме из PDF.** Разбор на правилах в памяти: ФИО, контакты, город, стек и софт-скиллы, роли,
  места работы, образование, «О себе», формат работы, переезд, стаж и подсказка грейда. Понимает
  выгрузки hh.ru, LinkedIn и Habr Career и резюме в свободной форме.
- **Защита от фиктивных работодателей.** Проверка ИНН, квоты по уровню доверия, сверка вилки с
  рынком, жалобы с автоограничением, модерация, репутация из фактов
  ([docs/TRUST_AND_ATS.md](docs/TRUST_AND_ATS.md)).
- **Интеграция с ATS.** Подписанные HMAC-SHA256 вебхуки через outbox с повторами и
  `SKIP LOCKED`, защита от SSRF, журнал доставок, песочница-приёмник, выгрузка CSV/JSON с
  аудитом.
- **Кабинет методиста.** Банк заданий с параметрами IRT, долей показов и живой генерацией
  экземпляров; экран «Вакансия → тест»: категория вакансии, состав теста под её стек, задания у
  порога грейда и навыки, которые проверяют микрозадачи; пороги грейдов с аудитом изменений.
  Работодатель видит тот же расчёт по своей вакансии — без заданий.
- **152-ФЗ.** Раздельные согласия; «Мои данные» в меню аккаунта: копия всех данных одним JSON и
  удаление аккаунта с уничтожением данных.
- **Мобильная вёрстка.** Все экраны проверены на ширине 375 px.
- **Валидация и нагрузка.** Подбор и тест проверены в цифрах ([docs/VALIDATION.md](docs/VALIDATION.md)),
  нагрузочный тест — [docs/LOAD_TEST.md](docs/LOAD_TEST.md).

Проверки: 497 тестов бэкенда на реальном PostgreSQL, 6 тестов эмулятора ФСП, 78 тестов
фронтенда, ruff и mypy в строгом режиме, eslint, tsc и проверка правил комментариев — всё это же
запускает CI.

## Локальная разработка

Для запуска стенда этот раздел не нужен. Он для разработки и проверок кода: нужны Python 3.13 с
[uv](https://docs.astral.sh/uv/), Node.js 22.22+, Docker и `make` (есть в Linux и macOS; на
Windows — в WSL 2).

```bash
make install        # зависимости бэкенда и эмулятора ФСП (uv) и фронтенда (npm)
make dev-backend    # PostgreSQL, Mailpit и эмулятор ФСП в Docker, API с автоперезагрузкой на :8000
make dev-frontend   # Vite на :5173, /api проксируется на :8000
```

Все команды перечислены в `make help`. Основные:

| Команда | Что делает |
|---|---|
| `make test` | тесты бэкенда (pytest на реальном PostgreSQL), эмулятора ФСП и фронтенда (vitest) |
| `make lint` | ruff, mypy в строгом режиме, eslint, tsc и проверка правил комментариев |
| `make openapi` | выгрузка `docs/openapi.json` и перегенерация TS-типов клиента |
| `make simulate` | симуляция адаптивного теста и отчёт в `docs/validation` |
| `make validate-assessment` | валидация теста: оценщики, разделяющая сила, утечки |
| `make eval-matching` | оценка подбора на размеченных парах в отдельной базе `fsp_scout_eval` |
| `make validation-report` | собрать `docs/VALIDATION.md` из отчётов |
| `make load-stand`, `make load-test` | стенд с 1050 кандидатами и нагрузочный тест |
| `make submission` | сопроводительная документация в PDF и DOCX (нужен pandoc) |
| `make vps-up`, `make vps-check DOMAIN=…` | развёртывание на VPS и проверка снаружи |
| `make revision m="…"` | новая миграция Alembic |
| `make reset` | остановка стенда с удалением данных БД |

Тесты бэкенда создают отдельную базу `fsp_scout_test`, применяют к ней миграции с нуля и
изолируют каждый тест транзакцией.

## Структура

```
backend/            FastAPI: api → services → crud → models, schemas, core, Alembic, тесты
frontend/           React 19 + Vite + Mantine: app, api, features, layouts, pages, shared/ui
fsp-registry-mock/  эмулятор ФСП ID (OIDC) и реестра достижений, генератор участников
keycloak/           realm ФСП ID для полноценного Keycloak (docker-compose.keycloak.yml)
docs/               подход, методики, валидация, архитектура, нагрузка, развёртывание, OpenAPI, документация для сдачи
deploy/             оверлей для VPS: Caddy с HTTPS, переменные и проверка развёрнутого стенда
tools/              проверка правил кода (комментарии на русском, только внутри функций), списки библиотек и API
docker-compose.yml  db (PostgreSQL 16 + pgvector), backend, frontend (nginx), fsp-registry-mock, mailpit
```

Слои, модули и данные — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
