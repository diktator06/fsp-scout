# Скаут

Платформа подбора ИТ-специалистов с **обратной механикой** и верифицированным профилем участника
Федерации спортивного программирования (ФСП). Работодатель сам находит кандидата в базе, где
специалисты разложены по категориям, и приглашает его с обязательной вилкой зарплаты. Категорию
кандидату присваивает не резюме, а опрос и адаптивный тест.

Спецтрек ФСП, «Лидеры цифровой трансформации 2026». Архитектура и план — в
[ARCHITECTURE_AND_PLAN.md](ARCHITECTURE_AND_PLAN.md).

## Быстрый старт

Нужен только Docker (Compose v2). Интернет нужен только для сборки образов, сам стенд работает
полностью офлайн.

```bash
docker compose up --build
```

| Что | Адрес |
|---|---|
| Приложение | http://localhost:8080 |
| Swagger UI (работает без интернета) | http://localhost:8080/api/docs |
| OpenAPI-спецификация | http://localhost:8080/api/openapi.json |
| Mailpit — письма подтверждения email | http://localhost:8025 |
| ФСП ID и реестр достижений (эмулятор) | http://localhost:8090 |

При старте бэкенд сам применяет миграции и наполняет справочники: 7 специализаций в 4
IT-направлениях, 4 грейда, 28 категорий, 152 навыка с алиасами и 75 парами родственных,
12 предметных областей, 18 компетенций и 79 семейств заданий. Затем создаёт демо-популяцию
и привязывает часть кандидатов к участникам эмулятора ФСП (первый старт дольше на 20–30
секунд, весь стенд поднимается меньше чем за минуту). Файл `.env` не обязателен: все значения по
умолчанию заданы в `docker-compose.yml`, а для переопределения есть шаблон
[.env.example](.env.example).

### Демо-аккаунты

Тестовые учётные записи локального стенда, пароль у всех `ScoutDemo2026`. На странице входа их
можно подставить одной кнопкой.

| Роль | Email |
|---|---|
| Специалист | `candidate@example.com` |
| Работодатель | `employer@example.com` |
| Методист | `methodist@example.com` |

Чтобы проверить регистрацию с нуля: зарегистрируйтесь на http://localhost:8080/auth/register,
откройте письмо в Mailpit и перейдите по ссылке — аккаунт подтвердится, и откроется кабинет.

### Участники ФСП в эмуляторе

Боевого ФСП ID у команд нет, поэтому в стенде работает эмулятор с тем же протоколом (OIDC, как у
Keycloak). Участники вымышленные, пароль у всех `FspDemo2026`. На странице входа эмулятора
четыре демо-персоны выбираются одной кнопкой:

| Логин | История в реестре |
|---|---|
| `fsp000021` | 7 соревнований, побед и призов: 6 |
| `fsp000030` | 3 соревнования, одно призовое место |
| `fsp000012` | одно участие без призового места |
| `fsp000007` | ФСП ID есть, участий нет |

## Что уже работает

- Регистрация специалиста или работодателя с обязательным согласием на обработку ПДн и
  подтверждением email. Пока email не подтверждён, войти нельзя.
- Вход, access-JWT (claims совместимы с Keycloak) и ротация refresh-токена в httpOnly-cookie.
  При повторном использовании отозванного токена отзывается вся цепочка сессий.
- Ролевой доступ `candidate` / `employer` / `methodist` на API и на маршрутах фронтенда.
- Справочники: специализации по IT-направлениям, грейды, категории, предметные области, навыки
  с поиском по алиасам («питон» → Python). Изменение справочников доступно только методисту.
- **Путь кандидата.** Онбординг из трёх шагов: анкета, опрос о стеке с превью состава теста и
  выбор уровня. Заявленный грейд виден с пометкой «не подтверждён», пока его не подтвердит тест.
- **Адаптивный тест** на 79 параметрических семействах заданий: у каждого кандидата свои
  экземпляры, ключ ответа не покидает сервер. IRT 3PL, EAP и классификационное правило
  остановки. Полный режим — 12–20 заданий, экспресс для демонстрации — 6–8. Результат
  показывается на шкале способностей с интервалом и разбором по темам. Методика и валидация —
  в [docs/ASSESSMENT.md](docs/ASSESSMENT.md).
- Профиль с навыками, опытом и образованием, база зарплаты (до вычета НДФЛ или на руки),
  выгрузка в PDF. Настройки приватности и отдельное согласие на публикацию в банке кандидатов.
- **Путь работодателя.** Профиль компании и потребность из свободного текста: разбор находит
  стек (must/nice), грейд, формат, город и вилку и показывает, откуда взято каждое поле. Дальше
  рекомендованные категории с рыночным срезом и ранжированная подборка с баллом, разложением и
  блоком «Почему в подборке». Уточнение создаёт новую версию, закреплённые кандидаты не
  теряются. Банк кандидатов с фильтрами. Механика описана в [docs/MATCHING.md](docs/MATCHING.md).
- **Приглашения.** Вилка «от–до» обязательна и не шире чем вдвое, база НДФЛ указана явно. Статусы
  «отправлено → просмотрено → принято / отклонено» видны обеим сторонам, контакты кандидата
  раскрываются только после принятия, раскрытие пишется в аудит. Уведомления в кабинете и письма
  в Mailpit.
- **ФСП.** Привязка ФСП ID по OIDC (код авторизации с PKCE, проверка RS256 по JWKS) с отдельным
  согласием на данные реестра, синхронизация участий, отвязка с удалением данных и вход через ФСП
  ID. Балл `F = min(1; 0,6·R + 0,4·N)` без ранжирования по уровню и дисциплине входит в индекс
  профиля. Состояния «не привязан», «привязан без участий» и «скрыто» штатные и не штрафуются.
  Работодатель видит сводку, лучший результат и протоколы, может отфильтровать «есть ФСП».
  Подробности — в [docs/FSP_INTEGRATION.md](docs/FSP_INTEGRATION.md).

### Демо-данные

При первом старте создаются около 120 вымышленных кандидатов по семи специализациям: каждый
проходит адаптивный тест настоящим сервисом оценки. Также создаётся демо-компания «Кедр
Технологии» с двумя потребностями у `employer@example.com`. Синтетические кандидаты входят как
`demo.<специализация>.<номер>@example.com` (например, `demo.backend.01@example.com`) с тем же
тестовым паролем. Это нужно, чтобы посмотреть приглашение глазами кандидата. Около 40 % из них
привязаны к участникам эмулятора ФСП: пары подобраны так, что история соревнований коррелирует
с результатом теста, а среди привязанных есть и участники без истории.

### Как быстро посмотреть подбор

Войдите как `employer@example.com` → «Подборки» → «Python-разработчик в команду платежей».
Пригласите кандидата из выдачи, войдите им и примите приглашение — у работодателя откроются
контакты.

### Как быстро посмотреть ФСП

Войдите как `candidate@example.com` → «Достижения ФСП» → отметьте согласие → «Привязать ФСП ID».
На странице эмулятора выберите `fsp000021`: вернётесь с семью участиями, баллом F и его вкладом
в индекс. Потом выйдите и нажмите «Войти через ФСП ID» — откроется тот же кабинет. У работодателя
в банке включите «Есть подтверждённые участия в ФСП» и откройте карточку: внизу лента участий
со ссылками на протоколы.

### Как быстро посмотреть тест

Войдите как `candidate@example.com` и пройдите онбординг. На последнем шаге выберите режим
«Экспресс»: тест займёт 6–8 заданий, после чего появится категория.

## Локальная разработка

Нужны Python 3.13 с [uv](https://docs.astral.sh/uv/), Node.js 22.22+ и Docker для PostgreSQL.

```bash
make install        # зависимости бэкенда и эмулятора ФСП (uv) и фронтенда (npm)
make dev-backend    # PostgreSQL, Mailpit и эмулятор ФСП в Docker, API с автоперезагрузкой на :8000
make dev-frontend   # Vite на :5173, /api проксируется на :8000
```

Все команды перечислены в `make help`. Основные:

| Команда | Что делает |
|---|---|
| `make test` | тесты бэкенда (pytest на реальном PostgreSQL), эмулятора ФСП и фронтенда (vitest) |
| `make lint` | ruff, mypy в строгом режиме, eslint, tsc и проверка правил комментариев |
| `make openapi` | выгрузка `docs/openapi.json` и перегенерация TS-типов клиента |
| `make simulate` | симуляция адаптивного теста и отчёт в `docs/validation` |
| `make revision m="…"` | новая миграция Alembic |
| `make reset` | остановка стенда с удалением данных БД |

Тесты бэкенда создают отдельную базу `fsp_scout_test`, применяют к ней миграции с нуля и
изолируют каждый тест транзакцией.

## Структура

```
backend/            FastAPI: api → services → crud → models, schemas, core, Alembic, тесты
frontend/           React 19 + Vite + Mantine: app, api, features, layouts, pages, shared/ui
fsp-registry-mock/  эмулятор ФСП ID (OIDC) и реестра достижений, генератор участников
docs/               OpenAPI и сопроводительная документация
tools/              проверка правил кода (docstring и комментарии на русском, только внутри функций)
docker-compose.yml  db (PostgreSQL 16 + pgvector), backend, frontend (nginx), fsp-registry-mock, mailpit
```

Подробное дерево и роль каждого модуля — в §4
[плана архитектуры](ARCHITECTURE_AND_PLAN.md).
